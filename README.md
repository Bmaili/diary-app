# 浮生记

自用的安卓日记 app（2026-10-05 起改名“浮生记”，图标是一枚水墨圆相加朱印；包名和签名没变，覆盖安装即可）。日记以一天一个 Markdown 文件保存在手机上，任何 Markdown 工具都能读。需求与技术规格见 [SPEC.md](SPEC.md)。

当前进度：**第 1–4 阶段和第 5 阶段的部分候选功能已完成**。

- 本地写作：写日记、心情、标签、日历（带农历、节气、节日）、那年今日、每日诗词、搜索、导出 zip
- 同步：阿里云 OSS、GitHub 私有仓库，可都开、只开一个或都不开；从云端恢复
- 位置与天气：自动记录地址和天气，附近地点可选，可以插图，图片可配一句说明（可让 AI 看图写）
- 长按桌面图标有“写今天”快捷方式；日历的法定节假日联网自动更新
- AI：问答（“去过 XX 几次”）、人物 / 地点 / 标签抽取、月度和年度总结
- 写日记提醒、PIN 应用锁（可加指纹解锁）、给 AI 的补充说明（共用 + 分功能）
- 删除日记（“最近删除”保留 30 天可恢复）
- “宣纸水墨”的界面；丰富的动态效果（页面切换、列表浮现、日历跟手滑动、梅枝开花），设置里可关
- 单篇日记可以设置“不让 AI 读”
- 编辑快捷按钮（加粗、列表、待办等）和列表自动续行；同步的“核对云端”；按后端单独开关的云端加密

所有功能都可以不配置，不配置时 app 就是一个纯本地的日记本。

## 先在电脑浏览器里试用

需要 Node.js 20 或更高版本。

```bash
npm install
npm run dev
```

打开终端里显示的地址（通常是 http://localhost:5173），按 F12 切到手机视图。浏览器里的日记存在该网站的本地存储里，只用于试用。

## 自动打包（推荐）

每次往 GitHub 的 main 分支推代码，GitHub Actions 会自动跑单元测试、打包签名的 APK，并发布到仓库的 **Releases** 页面。在手机上登录 GitHub，打开仓库的 Releases，下载最新的 `diary-1.0.N.apk`，点开选“更新”就能覆盖安装，日记不会丢。全程不需要电脑和 Android Studio。

只改文档（`.md`）或端到端测试时不会触发打包。在仓库的 Actions 页面可以看到每次打包的进度；也可以在那里点 “Run workflow” 手动打包一次。

### 一次性设置：签名

仓库 Settings → Secrets and variables → Actions → New repository secret，添加 4 个：

| 名称 | 内容 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | 签名文件的 base64 文本 |
| `ANDROID_KEYSTORE_PASSWORD` | 签名文件密码 |
| `ANDROID_KEY_ALIAS` | `diary` |
| `ANDROID_KEY_PASSWORD` | 和签名文件密码相同 |

没加这些时，打包只检查能否编译，不发布（没有签名的 APK 装不上）。

**签名文件和密码务必另外备份**（比如存进密码管理器）。安卓只允许同一个签名的新版本覆盖旧版本；签名丢了就只能卸载重装，而卸载会删掉手机上的全部日记。

### 在自己电脑上用同一个签名打包（可选）

在 `android/` 下新建 `keystore.properties`（已在 .gitignore 里，不会提交）：

```
storeFile=/你的路径/diary-release.jks
storePassword=签名文件密码
keyAlias=diary
keyPassword=签名文件密码
```

这样在 Android Studio 里打的 release 包和自动打包的签名一致，可以互相覆盖安装。注意：直接点“运行”装上的是调试版，签名不同，和自动打包的版本不能互相覆盖。

## 打包成安卓 app（手动）

1. 安装 [Android Studio](https://developer.android.com/studio)，第一次打开时按向导装好 Android SDK。
2. 在本目录运行：
   ```bash
   npm install
   npm run cap:sync
   npx cap open android
   ```
   这会构建网页、复制到安卓工程，然后用 Android Studio 打开 `android/` 文件夹。第一次打开需要下载 Gradle 依赖，可能要几分钟。
3. 手机开启“开发者选项”和“USB 调试”，用数据线连上电脑，在 Android Studio 顶部选中你的手机，点绿色的运行按钮。

每次改了代码，重新运行 `npm run cap:sync` 再点运行即可。

### 国内网络

工程已改为从国内镜像下载构建工具：Gradle 本体走腾讯云镜像（`android/gradle/wrapper/gradle-wrapper.properties`），依赖库优先走阿里云 Maven 镜像（`android/settings.gradle` 开头），镜像没有的才去官方仓库。

如果仍然下载失败：

- Android Studio 第一次打开时还会下载 Android SDK 组件，这部分走 Google 的服务器，国内一般能连上但可能较慢；如果你有代理，可在 Settings → Appearance & Behavior → System Settings → HTTP Proxy 里填上。
- Gradle 本体也可以手动下载：用浏览器下载 `https://mirrors.cloud.tencent.com/gradle/gradle-8.14.3-bin.zip`，放到 `用户目录/.gradle/wrapper/dists/gradle-8.14.3-bin/<一串随机字符>/` 下（先让它失败一次，这个文件夹就会自动创建），再点 Try Again。

### 正式使用前务必做的事

- **签名文件要备份。** 想长期使用，请在 Android Studio 里用 Build → Generate Signed App Bundle / APK 生成一个签名文件（keystore），并把它和密码另外保存好。签名文件丢了就无法覆盖安装新版本，只能卸载重装，而**卸载会删除手机上的全部日记**。
- **升级时覆盖安装，不要先卸载。**
- **开启至少一个云端同步**，或定期在“设置 → 导出为 zip”备份。
- OPPO / vivo / 一加的系统可能会询问是否允许 app 自启动或后台运行。不需要：同步在你打开和离开 app 时进行。

## 配置各项服务

都在 app 的“设置”里。密钥只加密保存在手机上，不会写进日记文件夹，也不会同步。

### 阿里云 OSS

1. 在 OSS 控制台创建一个 Bucket，读写权限选“私有”，建议在 Bucket 设置里打开“版本控制”（误删后能找回）。
2. 在 RAM 控制台创建一个子账号，勾选“OpenAPI 调用访问”，记下 AccessKey ID 和 Secret。
3. 给子账号授权：只允许读写这个 Bucket（可以用自定义策略限定到 `diary/` 前缀）。
4. 在 app 的“设置 → 同步与备份 → 阿里云 OSS”里填 Endpoint（Bucket 概览页“外网访问”那一行，例如 `oss-cn-hangzhou.aliyuncs.com`）、Bucket 名、AccessKey，点“测试连接”，再回上一页打开开关。

### GitHub 私有仓库

1. 新建一个**私有**仓库，可以是空的。
2. 打开 GitHub 的 Settings → Developer settings → Fine-grained tokens，新建 token：Repository access 只选这个仓库，Permissions 里把 Contents 设为 Read and write。
3. 在 app 里填用户名、仓库名和 token，测试后打开开关。每次同步是一个 commit，GitHub 网页上能直接看日记。
4. 国内访问 GitHub 不稳定。失败会自动重试，不影响 OSS；也可以在“API 地址”里填你自己的反向代理。

### 高德（地址和附近地点）

1. 在高德开放平台控制台创建应用，添加 key 时**服务平台选“Web 服务”**（不是 Android 平台）。
2. 填到“设置 → 位置与天气 → 高德 key”。不填也行，那样只记坐标，不显示地址和附近地点。

### 和风天气（可选）

不填时用免费的 Open-Meteo，国内一般也能访问。想用和风天气：在控制台创建项目和 API KEY，再到“设置”里找到你账号专属的 **API Host**（形如 `xxxx.re.qweatherapi.com`），两样都填进 app。

### 云端加密（可选）

“设置 → 同步与备份 → 加密”。OSS 和 GitHub 各有一个开关，默认关闭，可以只开一个。第一次打开时要设置加密密码（可以让 app 生成一个随机密码），**请存进密码管理器**：忘了密码，云端备份就解不开了。

- 打开后云端的文件全部换成 `xxx.md.age`，旧的明文文件会被删除。但 GitHub 的提交历史和 OSS 的历史版本里还有以前的明文：GitHub 建议新建一个仓库再打开加密，OSS 需要在控制台删除历史版本。
- 文件名（日期）和大小不加密。
- 不用这个 app 也能解密，云端 `_encryption/README.md` 里有步骤，大致是：
  ```bash
  age -d -o key.txt _encryption/identity.age      # 输入加密密码，得到身份密钥
  age -d -i key.txt entries/2026/2026-10-04.md.age > 2026-10-04.md
  ```
- 换手机恢复时，app 会让你输入加密密码。
- AI 功能仍会把相关日记以明文发给 AI 服务，云端加密管不到这一点。

### AI 服务

“设置 → AI 服务 → 添加服务”，从模板选服务商（DeepSeek、通义千问、Kimi、智谱、OpenAI、Anthropic），填模型名和 API Key，点“测试”。

- 问答需要模型支持工具调用，测试结果会告诉你支不支持；抽取和总结不需要。
- 可以添加多个服务，分别指定问答、抽取、总结用哪个（抽取量大，适合用便宜的模型）。
- 第一次把日记发给某个服务前会弹窗确认。
- “给 AI 的补充说明”里写日记里的称呼和简写（“老地方”是哪里、某个昵称是谁），三项功能都会带上；“分功能的补充说明”里分别写问答、抽取、总结的风格和规则（回答多长、标签用哪些词、总结的口气）。
- 每个服务有“高级设置”：上下文长度、最大输出、温度、超时、额外请求参数（JSON）。用推理模型时如果回答被截断就调大最大输出；通义千问之类需要关思考的，在额外参数里填 `{"enable_thinking": false}`。
- 问答带上的历史轮数、每个问题最多查几轮，最少都是 10。
- 问答的回答边生成边显示，生成中可以点停止。服务不支持时自动改用普通方式。
- 月度总结：一个月日记太多、超出“上下文长度”时，会按周分几段读，再合成整月总结（进度会显示在第几段）。
- “设置 → AI 服务 → 系统提示词”：每项功能发给 AI 的完整提示词都能整段改、恢复默认。输出格式这类程序要用的部分由 app 自动接在后面，改不坏。只想补充几句时，用补充说明更省心：app 以后更新默认提示词时，补充说明不受影响；整段改过的版本则不会自动跟着更新（会提示你）。
- AI 标注要模型输出 JSON：服务支持时用约束解码（OpenAI 兼容的 `json_object`、Anthropic 的强制工具调用），不支持自动退回；输出不合格时会请它重写一次。
- 用推理模型（会先“思考”的）时，思考也占输出额度。如果额度用完还没写出正文，app 会自动加大额度重试一次；还不行会提示你调大“最大输出”或关掉思考，不会再存下一份空总结。
- 问答一个问题会让模型多轮查日记，查到的原文会越积越多。app 按“上下文长度”估算发送量，快超出时先省略较早的查询结果；每个回答下面显示这次用了多少 token。

### 自动同步的时机

改完日记后停笔 2 分钟才上传，期间再改会重新计时，所以短时间内反复修改只传一次（GitHub 也只多一个 commit）。切到后台时有没传的会立即传；下次打开 app 时也会补传。都可以在“同步与备份”里调整。日记每秒都保存在手机上，晚传不会丢。

### 不让 AI 读某一篇

编辑页顶栏的眼睛图标（删除和编辑按钮之间），点一下变成“AI 不读”。之后问答查不到它，月度、年度总结不读它，批量标注也跳过它。文件里记为 `ai_exclude: true`。已经生成过的总结会显示“源内容已变”，重新生成就不含这篇了；之前的问答记录里如果引用过，需要你自己删掉那段对话。

### 图片说明

插图后会弹出“图片说明”框，写一句话（可以不写，直接关掉）；阅读视图里点图片也能改。说明存成 Markdown 的替代文字 `![说明](../../attachments/…)`，显示在图片下面，AI 问答和总结读正文时也能读到。

框里的“AI 看图写一句”需要能看图的模型（如 qwen-vl、glm-4v、gpt-4o、Claude），在“设置 → AI 服务 → 各项功能用哪个”里给“图片说明”选一个。“设置 → AI 服务 → 图片说明”可以打开“插图后让 AI 写一句说明”，默认关：会把这张图（缩到 1024 像素）和日记开头发给 AI 服务。设为“不让 AI 读”的日记不会发。

### 法定节假日

日历上的“休 / 班”先用应用内置的数据（lunar-javascript，到 2026 年），再联网用开源项目 [holiday-cn](https://github.com/NateScarlet/holiday-cn) 的数据覆盖：启动后发现今年没有、或上次检查超过 3 天，就取今年和明年的安排（先走 jsDelivr，失败再走 GitHub）。国务院公布次年安排后几天内会自动出现。“设置 → 日记 → 节假日联网更新”可以关掉或立即更新。数据存在 app 设置里，不在 `diary/` 里。

### 删除日记

编辑页右上角的垃圾桶。删掉的日记和这天插的图片移到“设置 → 最近删除”，保留 30 天，可以恢复。“最近删除”只在手机上：开了同步的话，云端副本会在下次同步时删除（OSS 开了版本控制时历史版本还在；GitHub 的提交历史里也还在），恢复后会重新上传。

## 测试

```bash
npm test              # 单元测试 195 项：文件格式、索引、同步、加密、核对云端、坐标、LLM、PIN、提醒、编辑快捷操作等
npm run build && PLAYWRIGHT_BROWSERS_PATH=<浏览器目录> npm run e2e          # 第 1 阶段端到端测试
npm run build && PLAYWRIGHT_BROWSERS_PATH=<浏览器目录> npm run e2e:stages   # 第 2–5 阶段端到端测试，截图在 e2e/out/
```

端到端测试需要 Playwright 的 Chromium（`npx playwright install chromium`）。OSS、GitHub、高德、天气和 LLM 都用本地模拟服务器代替；OSS 的签名用阿里云官方 SDK 交叉校验过。

### 拿到手机上请重点试这几件事

1. **同步**：配好 OSS 或 GitHub，写一篇，退出编辑页，去控制台 / 网页看文件到了没有；再插一张图，确认图片也传上去且能打开。
2. **定位**：第一次写当天日记时会请求定位权限。看地址对不对、附近地点里有没有你所在的店。
3. **AI**：用真实服务问一句“这个月我去过哪些地方”，再对一篇日记点“AI 标注”。
4. **提醒**：打开提醒，把时间设成两三分钟后，锁屏等着。部分手机为了省电会晚几分钟；完全不弹的话，去系统设置里允许本 app 的通知和后台运行。
5. **应用锁**：设好 PIN，切到别的 app 再回来；打开“在最近任务里隐藏内容”后，看多任务界面是不是空白。
6. **从云端恢复**：最好用另一台手机或模拟器装一次，走一遍恢复。如果开了加密，顺便确认输密码那一步。
7. **编辑快捷栏**：点进正文，看按钮条是不是贴在键盘上方；用你平时的输入法在列表里按回车，看会不会自动接上 `- `。有的输入法回车的方式比较特别，如果没接上请告诉我是哪个输入法。
8. **加密密码**：在手机上设置时要算几秒，属于正常。
9. **拍照插图**：第一次点“拍照”会请求相机权限。拍完确认后应回到编辑页并插入照片；如果打开的是选文件而不是相机，请告诉我手机型号。
10. **动效**：打开日记、返回、切换底部标签、在日历上左右拖动换月。如果哪里卡顿，可以先在设置里关掉“动态效果”，再告诉我是哪一处。
11. **指纹解锁**：设置 → 应用锁 → 打开指纹解锁（会先让你验一次）。然后切到后台超过设定时间再回来，看是否自动弹出指纹框；点“用 PIN”取消后还能输 PIN。
12. **流式回答**：问一个问题，看回答是否一段段出来；中途点停止，已经出来的文字应该留下。
13. **新图标和“写今天”**：桌面上应显示“浮生记”和圆相图标（个别桌面要重启才刷新）。长按图标选“写今天”，app 没开时和在后台时各试一次，都应直接进入今天的编辑页。
14. **图片说明**：插一张图写一句说明，看阅读视图里是否显示在图片下面；配了能看图的模型的话，点“AI 看图写一句”。

## 和规格不同的地方

SPEC.md 里相应位置都已注明，这里汇总：

- 技术路线改为网页技术 + Capacitor（2026-10-04 决定）。
- 定位用 WebView 的系统定位，高德只用 Web 服务 API，不集成高德安卓 SDK。
- 密钥用 WebCrypto 不可导出密钥加密，而不是 Android Keystore（少一层硬件保护，不需要原生插件）。
- 没有 WorkManager：同步全在前台进行（打开、离开、回到前台时），失败在 app 内退避重试。
- AI 抽取写回时不更新 `updated`，否则会被误判为“抽取后又改过”。
- 选附近地点时加入 `places`，但不锁定这个字段，AI 仍可补充。
- 心情由 5 个按钮改为拖动条，默认不选。
- 云端加密、核对云端、编辑快捷栏、最近删除、AI 高级设置和上下文控制是规格之外加的功能，SPEC.md 第 5.2、6.1、6.1.1、7.1、7.2 节已补充。
- 阅读视图里单个换行显示为换行（CommonMark 默认会并成一段）。
- 第 5 阶段：做了 PIN 锁、指纹解锁、写作提醒、“给 AI 的补充说明”（而不是可编辑的完整提示词模板）；没做桌面小组件、把日记放到公共目录。
- 本地索引不用数据库，而是内存索引加一个 JSON 缓存文件；3650 篇冷启动重建约 1.5–2 秒，之后只增量更新。
- 自动保存是“有改动后最多 1 秒写一次”，而不是“停止输入 1 秒后写”。后者在持续打字时可能长时间不保存，达不到“最多丢 1 秒”的要求。
